# Lesson 23 — fs

## Core Concept

The `fs` module gives Node.js access to the filesystem.

Import:

```js
import fs from "node:fs";
```

It supports:
- callback-based async APIs
- synchronous APIs
- streams
- file descriptors
- directory operations

## Reading a File

Async callback style:

```js
fs.readFile("data.txt", "utf8", (err, data) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log(data);
});
```

## Writing a File

```js
fs.writeFile("output.txt", "Hello Node.js", (err) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log("File written");
});
```

## Appending

```js
fs.appendFile("app.log", "Server started\n", (err) => {
  if (err) console.error(err);
});
```

## Rename

```js
fs.rename("old.txt", "new.txt", (err) => {
  if (err) console.error(err);
});
```

## Delete

```js
fs.unlink("temp.txt", (err) => {
  if (err) console.error(err);
});
```

## Create Directory

```js
fs.mkdir("uploads", { recursive: true }, (err) => {
  if (err) console.error(err);
});
```

`recursive: true` helps create missing parent directories.

## Read Directory

```js
fs.readdir("uploads", (err, files) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log(files);
});
```

## Check File Metadata

```js
fs.stat("data.txt", (err, stats) => {
  if (err) return;

  console.log(stats.isFile());
  console.log(stats.isDirectory());
  console.log(stats.size);
});
```

## Synchronous APIs

Example:

```js
const content = fs.readFileSync("data.txt", "utf8");
```

This blocks the main thread until the operation completes.

## When Sync APIs Are Acceptable

They may be acceptable during:
- startup
- CLI scripts
- migrations
- one-off tooling

Avoid them in hot request paths of web servers.

Bad API endpoint:

```js
app.get("/file", (req, res) => {
  const data = fs.readFileSync("large.txt", "utf8");
  res.send(data);
});
```

This blocks all other work on that event loop while reading.

## Large Files

Do not load huge files fully into memory with `readFile`.

For large files prefer streams.

```js
const stream = fs.createReadStream("huge.csv");
```

This processes data incrementally.

## File Descriptors

At a lower level, files are referenced using file descriptors.

Typical lifecycle:

```text
open
  |
  v
file descriptor
  |
  v
read/write
  |
  v
close
```

Higher-level APIs often manage this for you.

## Production Use Cases

- reading config files
- logs
- static file generation
- uploads
- exports
- report generation
- file processing
- temporary files

## Race Conditions

This pattern can be unsafe:

```text
check if file exists
then create file
```

Between checking and creating, another process may change the state.

Prefer atomic filesystem operations where possible.

## Common Mistakes

- using sync methods in request handlers
- loading huge files completely into memory
- forgetting error handling
- trusting user filenames
- forgetting encoding and getting Buffer unexpectedly
- leaking file descriptors in low-level code

## Interview Questions

### Difference between readFile and readFileSync?

`readFile` is asynchronous and does not block the main JavaScript thread while waiting. `readFileSync` blocks until completion.

### Why use streams for large files?

Because streams process chunks progressively instead of loading the entire file into memory.

## Interview-Ready Summary

```text
fs
  -> files
  -> directories
  -> metadata
  -> sync APIs
  -> async callback APIs
  -> streams
```

For server applications, prefer non-blocking APIs and streams for large data.
