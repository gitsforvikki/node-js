# Lesson 25 — os

## Core Concept

The `os` module provides information about the operating system and machine where your Node.js process is running.

Import:

```js
import os from "node:os";
```

## Platform

```js
console.log(os.platform());
```

Examples:

```text
linux
win32
darwin
```

Useful for platform-specific behavior.

## Architecture

```js
console.log(os.arch());
```

Examples:

```text
x64
arm64
```

## CPU Information

```js
console.log(os.cpus());
```

This returns details about logical CPU cores.

Useful for:
- diagnostics
- capacity information
- worker planning

Do not blindly spawn one worker per reported CPU without understanding container CPU limits.

## Available Parallelism

Modern Node.js exposes:

```js
console.log(os.availableParallelism());
```

This is often more useful than simply counting `os.cpus().length` when deciding how much parallel work the runtime can reasonably use.

## Memory

```js
console.log(os.totalmem());
console.log(os.freemem());
```

Values are bytes.

Example conversion:

```js
const mb = os.freemem() / 1024 / 1024;
console.log(mb);
```

## Hostname

```js
console.log(os.hostname());
```

Useful in logs and distributed environments.

## Home Directory

```js
console.log(os.homedir());
```

## Temporary Directory

```js
console.log(os.tmpdir());
```

Useful for:
- temporary uploads
- intermediate processing
- export generation

## Uptime

```js
console.log(os.uptime());
```

Returns system uptime in seconds.

Do not confuse with process uptime:

```js
process.uptime();
```

## End-of-Line

```js
console.log(os.EOL);
```

Useful when generating platform-specific text files.

## Network Interfaces

```js
console.log(os.networkInterfaces());
```

Provides network adapter information.

Useful for diagnostics, not as a reliable method for discovering public IP addresses.

## Production Example — Diagnostics Endpoint

```js
const diagnostics = {
  platform: os.platform(),
  arch: os.arch(),
  hostname: os.hostname(),
  freeMemory: os.freemem(),
  totalMemory: os.totalmem(),
  uptime: os.uptime(),
};
```

Be careful not to expose sensitive infrastructure details publicly.

## Container Awareness

In Docker/Kubernetes, host-level information can differ from container-level limits.

For example:

```text
physical host
  32 CPUs

container
  limited to 2 CPUs
```

Production capacity decisions should respect runtime/container limits rather than naive host assumptions.

## Common Mistakes

- exposing full system details in public APIs
- assuming os.cpus().length equals usable CPU capacity
- confusing system uptime and process uptime
- using networkInterfaces to infer public networking

## Interview Question

### What is os.availableParallelism useful for?

It provides an estimate of the amount of parallelism available to the current process and is useful when planning worker concurrency.

## Summary

```text
os
  -> platform
  -> architecture
  -> CPU
  -> memory
  -> host info
  -> temp directory
  -> network diagnostics
```

Use it mainly for diagnostics, tooling and runtime-aware behavior.
